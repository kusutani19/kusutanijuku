# レトロRPG成績動画

生徒の成績データを、ドット絵・二重枠・黄色い点数・伸びるEXPゲージの動画にする。付属レンダラーは、クスタニ塾で作成した「KUSUTANI QUEST」の見た目を再現する。過去の動画、生成スクリプト、チャットの添付ファイルは不要。

## 作業の進め方

1. ユーザーの一覧から学校、学年、テスト名、5教科合計点、自己ベスト更新の有無を抽出する。順番と表記を保持する。未提示の前回点・上昇幅・順位・氏名は作らない。「自己ベスト」と明記された例だけを強調する。
2. 塾名は指定を優先し、この案件の既定値は **クスタニ塾**。「クスター塾」など参考映像の別表記に変更しない。入力が十分なら確認待ちにせず制作する。点数など必須情報が欠ける場合のみ質問する。
3. 下記JSONを作業用フォルダーに作る。出力は過去の成果物を上書きしない新規フォルダーにする。既存チェックアウトを使い、要求がなければworktreeを作らない。
4. 依存関係を確認し、付属スクリプトで実際にレンダリングする。
5. 成績一覧と照合し、画像と動画を検証する。
6. 利用可能な方法で動画を渡す。受け渡し先への保存は既存の明示的な許可に従う。

## デザインを保持する

- 画面：9:16、1080×1920、30fps。540×960で描画し、nearest-neighborで2倍に拡大する。
- 背景：ほぼ黒の紺色。控えめな星の点滅。上部に等幅英字で `KUSUTANI QUEST`。
- 中央：画面幅の約90%のRPGウィンドウ。角丸や写実的クリスタルではなく、直角の二重枠。
- 左上：色違いのオリジナル8×8ドット顔。その右に学校・学年。テスト名を省略せず表示する。
- 中央：黄色い大きな点数と「点」。0から実点へ約0.55秒でカウントアップする。
- 下：EXPと伸びるゲージ。ゲージは **今回の得点÷満点**。前回との差を表すものではない。
- 通常例：紺色パネル、白い枠、緑のゲージ。「高得点 獲得！」「見事な高得点！ おめでとう！」。
- 自己ベスト：濃い金色パネル、黄色い枠とゲージ。上部に大きな **「自己ベスト更新！」**、右上にも赤文字のバッジ。英語だけで済ませない。
- 小さな黄色い▼を点滅させてゲームのメッセージ送りを表現する。
- 構成：導入3秒 → 各例3秒 → 結び4秒。16例なら55秒。結びは「つづく…」「クスタニ塾」「次の自己ベストへ！」。
- 音：付属スクリプトが合成するオリジナルのチップチューンと短い結果ジングル。既存ゲームの映像・キャラクター・ロゴ・楽曲を素材として組み込まない。

## 入力JSON

```json
{
  "brand": "クスタニ塾",
  "heading": "KUSUTANI QUEST",
  "max_score": 500,
  "intro_seconds": 3,
  "card_seconds": 3,
  "outro_seconds": 4,
  "results": [
    {
      "school": "柏中",
      "grade": "3",
      "test": "1学期期末テスト",
      "score": 493,
      "personal_best": true
    }
  ]
}
```

`grade`は文字列、`score`は整数、`personal_best`は真偽値。未指定の`personal_best`はfalse。順序は入力順。1〜100例、満点1〜9999点、各表示時間1〜30秒に対応する。5教科合計用のテンプレートなので、単教科や得点上昇の比較を依頼された場合はラベルとレイアウトを明示的に調整してから検証する。

今回の16例は `examples/kusutani-16.json` に保存済み。新規依頼のデータに古い16例を勝手に混ぜない。

## 実行

`SKILL_DIR`をこのSKILL.mdがあるディレクトリの絶対パスに設定する。Python 3.10以降、FFmpeg（libx264/AAC対応）、Pillow、NumPy、日本語フォントが必要。

```bash
python -m pip install -r "$SKILL_DIR/scripts/requirements.txt"
python "$SKILL_DIR/scripts/render.py" \
  --data "$SKILL_DIR/examples/kusutani-16.json" \
  --output-dir /workspace/outputs/quest-new
```

FFmpeg、日本語フォントがなければ環境のパッケージ管理方法に従い導入する。Linuxの標準例は `ffmpeg fonts-noto-cjk fonts-dejavu-core`。フォントの場所が違う環境では `--font` に日本語TTF/OTF/TTC、`--mono-font` に等幅フォントを指定する。依存関係は必要に応じて仮想環境へ導入する。入力データや成果物をスキル本体の中に出力しない。

生成物：`results.mp4`、`quest_preview.jpg`、`quest_end.jpg`、`quest_music.wav`、`manifest.json`。manifestには使用データ、件数、自己ベスト件数、尺を記録する。これは内部照合用であり、不要に公開しない。

## 完成前の検証

- 入力の全例について学校・学年・テスト名・点数を照合し、自己ベストの件数も数える。
- `quest_preview.jpg` と `quest_end.jpg` を画像表示ツールで開き、日本語、塾名、欠け・重なりを確認する。通常例や長い学校名も必要に応じてMP4から抽出して確認する。
- `ffprobe -v error -show_streams -show_format <results.mp4>` で1080×1920、30fps、H.264/AAC、予定尺を確認する。
- `ffmpeg -v error -i <results.mp4> -f null -` を実行し、**終了コード0**を確認する。プロセスの存在だけで成功扱いしない。
- 必要なら冒頭・中間・末尾のフレームを抽出する。長文は自動縮小されるが、読みやすさも確認する。
- 付属スクリプトの得点・満点・真偽値バリデーションを無効化しない。

## 受け渡し

ダウンロード可能な正式な添付機能があれば使用する。ローカルパスや `sandbox:` リンクを、動作未確認のままダウンロード可能と断言しない。このクラウド画面では以前それらのリンクが動作しなかった。

この制作では `kusutani19/kusutanijuku` を保存先として利用した。保存・公開の許可はその時点のユーザー指示で確認し、以前の会話の許可を持ち越さない。GitHub保存の許可がある場合はリモートと作業ツリーを確認し、対象ファイルだけをコミットしてpush成功を確認する。新しい動画名で `videos/` に保存し、既存作品を保持する。ユーザーにはGitHubのblobページと「Download raw file（下向き矢印）」の操作を案内する。非公開リポジトリはログインが必要。

最終報告は動画へのリンク、件数・尺、反映した演出を簡潔にまとめる。
